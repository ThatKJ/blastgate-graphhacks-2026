Step 2

Scroll down to the Agent investigation section. Inspect the 5-step MCP tool timeline:

  • inspect_change: Discovers producer pricing-engine.
  • inspect_contract_coverage: Identifies checkout-api has no fallback.
  • trace_blast_radius: Discovers downstream cascade to order-orchestrator.
  • analyze_network_criticality: Identifies betweenness centrality of 4.0 (highest) on order-orchestrator.
  • retrieve_incidents_and_reviewers: Connects past outage INC-2041 and assigns reviewers eng-alpha and eng-bravo.

Step 3

Inspect the Deterministic BLOCK Verdict & Evidence

Observe the massive high-signal BLOCK stamp. Notice the two explicit graph reasons:

  1. A breaking change reaches a consumer without fallback (checkout-api).
  2. Impacts critical services with $43,000 assumed SLA risk across SLA-CHECKOUT-99.95 and SLA-ORDERS-99.9.

Click nodes and edges in the interactive Impact map & graph evidence explorer. Selecting checkout-api updates the Evidence Inspector with exact FalkorDB node attributes and Cypher paths.

✓ Demonstrates: Actions based on graph evidence & fully explainable results.
Step 4

Simulate a Counterfactual Mitigation

Scroll down to the Counterfactual simulation panel. Select consumer checkout-api, keep the assumption "checkout-api adds a backward-compatible fallback for discount_tier", and click "Run simulation".

Observe the side-by-side comparison:

  • Active graph: Verdict remains strictly BLOCK (production untouched).
  • Simulated graph: Cloned onto GRAPH.COPY in FalkorDB; verdict shifts to CLEAR.
  • Topology Diff: Shows 1 edge safely mitigated and risk dropped to $0. Explicitly marked UNVERIFIED.
✓ Demonstrates: Safe isolated counterfactual reasoning without mutating production state.

Local Setup & Reproduction Commands

Everything needed to run the complete stack from source.

1. Start FalkorDB in Docker

docker run -p 6379:6379 -d --name blastgate-falkordb falkordb/falkordb:latest

2. Create Virtual Environments & Seed Service Graph

python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python blastgate_milestone1.py

3. Generate Code-Graph Review with Gristle

./scripts/setup_gristle.sh
BLASTGATE_GRISTLE_BIN=.gristle-venv/bin/gristle BLASTGATE_MEMORY_GRAPH=blastgate_memory .venv/bin/python scripts/codegraph_demo.py

4. Launch Demo Server

PORT=8766 ./scripts/start_demo.sh

The application and console are served on: http://127.0.0.1:8766/

5. Run Verification Regression Suites

# Run full pytest suite (217 passed, 11 skipped)
.venv/bin/pytest

# Run frontend Node view test suite (25/25 passed)
node --test web/tests/view.test.mjs

# Run live Gristle integration tests
BLASTGATE_GRISTLE_BIN="$(pwd)/.gristle-venv/bin/gristle" .venv/bin/pytest tests/integration/test_codegraph_live.py

Self-Diagnostics & Troubleshooting

Port 8766 in use

Another BlastGate instance or process is using port 8766. Run with an alternate port:

PORT=8770 ./scripts/start_demo.sh

FalkorDB unreachable

Ensure the Docker container is active: docker ps. Restart if stopped:

docker start blastgate-falkordb

Missing codegraph_demo_out/report.json

Generate the AST review report before starting the server:

.venv/bin/python scripts/codegraph_demo.py

Verify Server Readiness

Check the backend health and readiness endpoints directly:

curl -s http://127.0.0.1:8766/ready
